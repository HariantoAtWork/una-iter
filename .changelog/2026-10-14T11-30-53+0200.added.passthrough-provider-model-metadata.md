# Pass provider model metadata through to clients

The models drawer and the public model list only knew a handful of fields, so any
context-length or other detail a provider advertised in its `/models` entry was lost.

When retrieving models from an OpenAI-compatible provider, the full raw `/models`
entry is now stored per model as `providerMeta`, and a context length is derived from
it (known keys such as `context_length`/`max_context_length`/`context_window`/
`max_model_len` first, then any context-ish numeric field as a fallback) and shown in
the drawer as a compact token count (for example `128K ctx`). The public
`GET /v1/models` now copies those stored provider fields through to clients, while
`id`, `object` and `owned_by` stay under our control so `{slug}/{model}` routing keeps
working. Both stored fields survive export/import round-trips.
